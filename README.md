# BidirectAuth-MQTT

> Bidirectional Authentication for MQTT clients using Arrowhead Framework + HiveMQ + RSA Cryptography

Standard MQTT authenticates the client to the broker but never the other way around. A fake broker could intercept all credentials and clients would never know. This project fixes that by implementing **mutual authentication** — both the client and broker cryptographically prove their identities before any data flows.

---

## What This Project Does

- **Client → Broker:** Client proves identity using an Arrowhead-issued JWE token
- **Broker → Client:** Broker proves identity via RSA signature (brokerProof) over fresh nonces
- **Chain of Trust:** Broker public key delivered inside an Arrowhead-signed JWT
- **Replay Protection:** Every CONNECT uses a fresh clientNonce with 5-minute TTL cache
- **Per-Packet Authorization:** Every PUBLISH and SUBSCRIBE checked against JWT sid claim

## Token Types

### Token A — Client-JWE (Service Authorization)
Generated by Arrowhead, encrypted with broker public key (RSA-OAEP-256 + AES-256-CBC). Only the broker can decrypt it.

```json
{
  "jti": "vBhMXrndxC8DjqW7_Wk6nQ",
  "iss": "Authorization",
  "cid": "temperature-sensor.smarthome.demo",
  "sid": "temperature-reading",
  "iid": "HTTP-SECURE-JSON"
}
```

### Token B — Broker-Credential-JWT
Plain JWT signed by Arrowhead private key. Contains broker RSA public key. Sent in CONNACK so clients can verify broker identity without hardcoded files.

```json
{
  "iss": "Arrowhead",
  "sub": "hivemq-broker.smarthome.demo",
  "brokerUrl": "127.0.0.1:8883",
  "brokerPub": "-----BEGIN PUBLIC KEY-----\nMIIBIjAN...",
  "exp": 1777726606
}
```

## Full Authentication Flow

Client → Arrowhead Orchestrator
POST /orchestrator/orchestration
{ "requestedService": "temperature-reading" }
Arrowhead → Client
{ "broker": "127.0.0.1", "port": 1883, "token": "<JWE>" }
Client → HiveMQ  (MQTT CONNECT)
password       = Token A (JWE)
userProperties = { clientNonce: "d296741851764247..." }
HiveMQ Extension validates:

Decrypt JWE with broker.priv
Verify inner JWT with Arrowhead.pub
Check clientNonce not replayed (5-min TTL store)
Generate brokerNonce
Compute brokerProof = RSA_sign(clientNonce || brokerNonce, broker.priv)


HiveMQ → Client  (MQTT CONNACK)
userProperties = {
brokerNonce:      "9fa366b011d91046...",
brokerProof:      "JbiXMX35rPvcd2Bb...",
brokerCredential: "eyJhbGci..."
}
Client validates:
a. jwt.decode(brokerCredential, arrowhead_pub_key)
b. extract broker.pub from validated JWT
c. broker_pub_key.verify(brokerProof, clientNonce + brokerNonce)
MUTUAL AUTHENTICATION COMPLETE
Per-packet: Every PUBLISH/SUBSCRIBE re-validates Token A
sid "temperature-reading"   → PUBLISH to room/temperature  ALLOWED
sid "temperature-reading"   → PUBLISH to room/lights       DENIED
sid "temperature-subscribe" → SUBSCRIBE room/temperature   ALLOWED

## Security Features

| Feature | Mechanism |
|---------|-----------|
| Client authentication | JWE token signed + encrypted by Arrowhead |
| Broker authentication | RSA brokerProof over fresh nonces |
| Replay protection | clientNonce stored with 5-min TTL |
| Chain of trust | Broker public key inside Arrowhead-signed JWT |
| Per-packet authorization | sid claim maps to topic + action |
| Session binding | brokerProof signs both clientNonce AND brokerNonce |

## Quick Start

### 1. Generate Certificates
```bash
bash mk_certs.sh
python3 mk_broker_credential.py
```

### 2. Build HiveMQ Extension
```bash
cd hivemq-extension && mvn clean package -q && cd ..
rm -rf hivemq-ce-2024.3/extensions/smarthome-auth-extension
unzip -q hivemq-extension/target/smarthome-auth-extension-1.0.0-distribution.zip -d hivemq-ce-2024.3/extensions/
rm -f hivemq-ce-2024.3/extensions/smarthome-auth-extension/DISABLED
```

### 3. Start All 6 Services
```bash
java -jar serviceregistry.jar   # Terminal 1
java -jar authorization.jar     # Terminal 2
java -jar orchestrator.jar      # Terminal 3
./hivemq-ce-2024.3/bin/run.sh  # Terminal 4
python3 mqtt-client/temperature_sensor.py   # Terminal 5
python3 mqtt-client/smart_thermostat.py    # Terminal 6
```

### 4. Verify Working
```bash
grep "Loaded Broker-Credential-JWT" hivemq-ce-2024.3/log/hivemq.log
grep "PUBLISH.*ALLOWED" hivemq-ce-2024.3/log/hivemq.log | tail -5
```

Expected sensor output:
[SENSOR] Broker credential validated: hivemq-broker.smarthome.demo
[SENSOR] Broker public key extracted from validated credential
[SENSOR] brokerProof VALID - broker identity confirmed
[SENSOR] MUTUAL AUTHENTICATION COMPLETE

## Attack Tests

```bash
# Replay Attack
sed -i \'\' \'s|secrets.token_hex(16)|"00000000000000000000000000000001"|\'  mqtt-client/temperature_sensor.py
python3 mqtt-client/temperature_sensor.py  # second run: REJECTED

# Wrong Topic
sed -i \'\' \'s|"room/temperature"|"room/lights"|\'  mqtt-client/temperature_sensor.py
# PUBLISH DENIED - Topic mismatch

# Fake Broker
python3 attack/fake_broker.py
# brokerProof INVALID - broker does not hold private key

# Tampered Credential
echo "tampered" >> certificates/hivemq-broker.token
# Broker credential signature INVALID
```
